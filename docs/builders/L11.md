# L11: Benchmarks and the gate report

Branch `l11-bench`, cut from `main` after L10 merged. Folder `bench/`. Raw numbers go to `D:\Build Artifacts\ore\bench\`.

## Build and measure
1. **G4 speed:** 8 kernels, each written in Ore, Rust and Python, with the same input and output so the outputs can be compared:
   - n-body (1M steps), binary-trees (depth 16), fannkuch-redux (10), spectral-norm (1,000);
   - a 10 MB JSON round trip, sorting 1M Ints, 1M map inserts with lookups, building a 50 MB string from parts.
   - Ore runs as `.cwasm` through `ore run`; Rust is `--release`; Python is CPython 3.12.
   - Median of 5 runs each, wall time, on an idle machine (note anything else running).
   - Report Ore against Rust and Ore against CPython per kernel, with the geometric mean. The fuel counter stays on; also run once with fuel off and report the difference.
2. **G5 check time:** a warm `ore check` of 1,000 lines, then a second unchanged check (the store's cache).
3. **G2 again:** L5's 30 change requests, on the finished toolchain and through the MCP tools, with Sonnet and Codex.
4. **G1 and G3 again:** the 40-task subset with Sonnet and Codex, through `ore mcp` (Rust toolchain, not the spike).
5. **G6 and G7:** quote L8's escape-suite result and the frozen card's size.

## Report
`bench/REPORT.md`: one table of every gate (G1–G7) with target, measured value, pass or miss, and the command that measured it. Then one paragraph per miss: why it missed and what would fix it. The coordinator copies the table onto the plan page.

Gate: the report itself. Plus one `python scripts/cargo.py check --workspace`.
