# L3: Core and reference interpreter (Rust)

Branch `l3-core`, cut from `main` after L2 merged. Crate `crates/ore-core`. Extend `ore-cli`.

From here on, the Rust interpreter is the judge of meaning. L6 lowering and L7 WASM are checked against it, and it has to agree with the spike first.

## Build
1. **Core IR** (`ore-core/src/core.rs`), about 20 node kinds:
   - literals (Int i64, Float f64, Str, Bool, Unit);
   - `Local(de Bruijn index)`, `Global(def id)`, `Builtin(id from data/library.json)`;
   - `Con(type, tag, arity)`, `Lam(n params, body)`, `App(f, args)`;
   - `Let(pat, rhs, body)`, `LetRec(rhs, body)`, `Seq`, `Match(scrutinee, arms(pat, guard, body))`, `If`, `Catch(body, handler, handler_takes_message)`;
   - `Prim(op, a, b)` for binary operators, `Neg`, `Not`;
   - `Field(label)`, `Slot(i)`, `Index`, `Tuple`, `List(items with spread flags)`, `Record(fields, spreads)`, `Map(entries, spreads)`, `Concat`/`Str` for `$` strings.
   - Patterns stay structured in Core; L6 compiles them to decision trees.
   - Names are erased; a side table maps ids back to names, for diagnostics only.
   - This is the contract L4–L7 build on, so keep it small and document each node in one line.
2. **Desugar** from the `ore-syntax` AST:
   - `a | f` becomes `App(f, [a])`; `f >> g` becomes `Lam(1, App(g, [App(f, [Local 0])]))`.
   - Clauses become a `Lam` over a `Match` on the argument tuple, with guards falling through to the next clause.
   - Local function bindings become `LetRec`; `$` strings become concatenation with `str`; operator sections become two-argument lambdas.
   - Records and maps are decided by keys, as in the spike (`copy` kind resolved at run time from the spread's value).
3. **Interpreter** with the spike's exact semantics:
   - Values: Int (i64), Float, Str (`Rc<str>`), List (`Rc<Vec>`), Map (insertion ordered; `indexmap` is fine), Record, Con, Tuple, Unit, Fn (closure, partial application, builtin).
   - Currying and over-application as in `Interp.apply`.
   - `fail` is a Rust `Err`; `catch` handles it. Capability errors (C001) and fuel errors (C002) are not catchable.
   - Int overflow fails (`fail "int overflow"`); the spike uses Python big ints, so add the same check to the spike.
   - `show` must print exactly what the spike prints. Floats follow Python's `repr` (shortest round trip, `1.0` keeps its `.0`, exponents written like `1e+16`), and strings are JSON-quoted when nested. Write a formatter and test it on a table of edge cases.
   - String verbs follow the spike's Python semantics (`words` = `str.split()`, `split sep`, `lines` = `splitlines`). If you diverge (for example, `lines` splitting only on `\n`, `\r\n` and `\r`), change the spike to match and list it.
4. **All library verbs** in `data/library.json`, implemented in Rust. L9 refines them later.
5. **CLI:**
   - `ore check FILE` runs the tests and prints the spike's output lines, including failing-test records with `left` and `right`.
   - `ore run FILE --allow io,fs --fuel N` works as in the spike. Fuel decrements per call.
   - Every line must be byte-identical to the spike's output for the same input.
