# L10: Agent surface

Branch `l10-agent`, cut from `main` after L8 merged.

## Build
1. **`ore mcp`:** an MCP server over stdio (JSON-RPC 2.0) inside `ore-cli`, with no SDK. Implement `initialize`, `tools/list` and `tools/call`. Each tool works on a project folder (`root`, default the current folder, with its `.ore/store.db`):
   - `ore_check {src | path}`: types, effects, diagnostics with fixes, test results.
   - `ore_add {src}`, `ore_edit {name, line}`, `ore_get {names}`, `ore_ls {}`, `ore_find {type | text}`.
   - `ore_run {name | src, grants, fuel, stdin}`, `ore_test {names?}`.
   - Every result is the same JSON the CLI prints, as text content.
   - Tool descriptions are short and written for a model. The `ore_check` description carries the card's file path, not the card.
2. **`ore check --fix`:** applies every mechanical fix (inserted brackets, alias replacements, `++` for `+`, wrapping with `int`, `float` or `str`) and prints the fixed text and the remaining diagnostics.
3. **Skill:** `skill/ore/SKILL.md` for Claude Code. When to reach for Ore (pure data transforms, roll-ups and checks an agent would otherwise script in Python), the card verbatim, and the loop: check, fix, add, edit by name, find before writing.
4. **`docs/INSTALL.md`:**
   - how to register the server in Claude Code: `claude mcp add ore -- <path>\ore.exe mcp`;
   - how to register it in Codex (`~/.codex/config.toml` `[mcp_servers.ore]`);
   - where the release binary lands.
   - Don't change Kyle's own config here; the coordinator does that at ship time.

## Gate (run once, at the end)
- A headless Claude Code run (`claude -p --mcp-config <file> --strict-mcp-config`, allowed tools limited to `mcp__ore__*`) finishes 20 L1 tasks (10 general, 10 domain) using only the MCP tools. Report passes, tool calls and output tokens per task.
- One `python scripts/cargo.py check --workspace`.
