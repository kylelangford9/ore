# L4: Types and effects (Rust)

Branch `l4-types`, cut from `main` after L3 merged. Crate `crates/ore-types`. Runs alongside L5 (store) and L9 (library). Touch `ore-syntax` only for the typed hole `?` (an atom where an expression is expected; the ternary `?` is infix and can't clash).

## Build
1. **Types:** `Int Float Str Bool ()`, tuples, `[a]`, `Map k v`, records as rows (`{k: T | r}`), ADTs with parameters, functions with an effect row (`a -> b ! e`), and type variables.
2. **Inference:** Hindley–Milner with let-polymorphism over Core, one recursive group at a time (`LetRec` and mutually recursive top-level definitions, in SCC order).
   - Row unification for records: field access, punning and spread or update.
   - Constructors come from `type` items; the arity check already exists (N003).
3. **Built-in constraint classes** (no user-defined traits in v1):
   - `num` (Int or Float), `eq`, `ord` (Int, Float, Str, and tuples or lists of `ord`), `show` (everything but functions), `hash` (map keys: Int, Str, Bool, tuples of `hash`).
   - Widening: binary arithmetic on two `num`s is Float if either side is Float, and `/` always gives Float. Solve it as a deferred constraint once both sides are known.
   - Unresolved `num` defaults to Int; an unresolved type left in a map key defaults by the same rules.
4. **Effect rows:** `fail io fs net time rand`.
   - Library effects come from `data/library.json`. Higher-order verbs are effect-polymorphic: `map`'s effect is its function's.
   - `catch` removes `fail` from its body's row.
   - `main`'s effects must be covered by the run's grants. `ore check` lists them; `ore run` refuses a missing grant before starting (C001), instead of failing halfway.
5. **Typed `json`:** `json s` gets the type its use requires.
   - Elaborate each call site with its target type so the interpreter decodes into exactly that shape: records for objects whose fields are used, maps when used as a map, lists, numbers and strings.
   - An open row closes to the fields actually used.
   - A shape mismatch is a `fail` with the path, for example `json: $.items[2].qty is a string`.
6. **Signatures** `f : T` are checked when present. They are never required.
7. **Diagnostics** (new codes T001…, listed in `docs/DIAGNOSTICS.md`):
   - A mismatch reports expected and found types, both spans, and a mechanical fix when there is one: wrap with `int`, `float` or `str`; use `++` instead of `+`; add `catch` for an uncaught `fail` in a test; the missing argument count for a partial application where a value was expected.
   - Types print compactly (`Str -> Map Str Float`), with effects as a separate list.
8. **Typed holes:** `?` reports the expected type and up to 10 in-scope names and library verbs that fit, as `{"k":"hole",...}`.
9. **CLI:** `ore check` adds one `{"k":"def","name":...,"type":...,"effects":[...]}` line per definition before the test results. Type errors stop the tests from running for that file.
10. The spike has no types. Write the spike's equivalent-behaviour notes in `docs/DIVERGENCES.md`: programs the spike runs but the checker rejects, each with the reason.

## Gate (run once, at the end)
- Every corpus program types: examples, `bakeoff/tasks/*/ref.ore` and the bake-off's passing model-written Ore programs. List any rejections, each one fixed or justified.
- **Negative suite:** 200 programs in `crates/ore-types/tests/neg/`, built from the bake-off's real failures where possible. Each gives its expected code.
- **G5:** a warm check of a 1,000-line file (concatenated corpus, renamed apart) in ≤ 50 ms in release mode.
- One `python scripts/cargo.py check --workspace`.
