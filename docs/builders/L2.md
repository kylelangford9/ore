# L2: Front end (Rust)

Branch `l2-front-end`. Crates: `crates/ore-syntax` (library) and `crates/ore-cli` (binary named `ore`).
L1 works on the bake-off at the same time and adds date verbs and a C-style surface mode to the spike. You build surface T only. If L1 switches the surface, a follow-up handles it.

## Build
1. **Shared data first.** Move the library's names, arities and effects out of the spike into `data/library.json`: `[{"name":"map","arity":2,"effect":null}, …]`. Move the alias table into `data/aliases.json`. Make `spike/ore.py` read both files; the Python implementations stay in the spike. The Rust side reads the same files at build time (`include_str!`). One source, no drift.
2. **AST** (`ore-syntax/src/ast.rs`): Rust enums mirroring the spike's tuple shapes exactly (`def`, `type`, `test`, `sig`; the expression and pattern kinds in `Parser` and `con_pat`). Every node carries a span: line, col and byte range.
3. **Lexer and parser:** the spike's grammar, precedence table, item splitting (a new item starts at column 1; indented lines continue), `$x`/`${e}` string holes, `_` lambdas scoped to the nearest parentheses (hole names `%0`, `%1` … in order), operator sections `(+)`, `match` with the no-brace scrutinee rule, the int-only lexing after `.`, and the speculation at lambda and binding heads. You may restructure the speculation as long as every program parses to the same tree. Recovery is per item: report every error in one pass, with the spike's codes, messages and `fix` objects.
4. **Name check:** same rules and codes as the spike (N001 with an alias or close-match fix, N002, N003, D001, D002), and the same "broken item names count as known" rule.
5. **Canonical printer:** `ore fmt FILE` prints one canonical text per tree. Nobody reads it (P2), so choose spacing for the fewest tokens. Try 2–3 spacing rule sets on the corpus with o200k (`spike/tokens.py` has the tokenizer loader) and keep the cheapest. Record the numbers in your report.
6. **CLI `ore`** (JSON lines only):
   - `ore parse FILE` prints the AST as JSON, positions omitted.
   - `ore check FILE` prints parse and name diagnostics, then a summary line. Tests come with L3's interpreter: until then the summary says `"tests":N,"run":false`.
   - `ore fmt FILE` prints the canonical text.
   - Add `python spike/ore.py ast FILE` to the spike, printing the identical JSON, so the two can be compared byte for byte.

## Gate (run once, at the end)
- **Differential parse:** `spike/examples/*.ore`, every `bakeoff/tasks/*/ref.ore` that exists on `main` or on L1's branch when you finish, and 2,000 generated programs. Write the generator as `spike/gen.py`: random well-formed items covering every construct, plus 200 deliberately broken ones. `ore parse` must equal `spike ast` on all of them, and the diagnostic codes and positions must equal the spike's on the broken ones. Report mismatches by kind; each one is either fixed or listed as a divergence with a reason.
- **fmt:** on the same corpus, `parse(fmt(src)) == parse(src)` and `fmt(fmt(src)) == fmt(src)`.
- **Speed:** parse plus name check of a 1,000-line file under 5 ms in release mode, measured with your own timer.
- One `python scripts/cargo.py check --workspace` at the end.

Dependencies: `serde` and `serde_json` only, unless something is clearly worth its build time.
