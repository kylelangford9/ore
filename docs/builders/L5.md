# L5: Store, hashes and edits (Rust)

Branch `l5-store`, cut from `main` after L3 merged. Crate `crates/ore-store`. Runs alongside L4 (types) and L9 (library). Until L4 merges, store the type as `null`. The coordinator wires L4 in at merge, or you do if L4 lands first.

This builder also measures G2, which is the second check of the stop rule.

## Build
1. **Canonical encoding and hash:** a compact byte encoding of Core with names erased (locals as de Bruijn indices, library calls as ids from `data/library.json`, constructors by type hash and tag) and BLAKE3 over it.
   - Mutually recursive definitions are hashed as one group (SCC), each member addressed as group hash plus index, with members ordered by their own name-free encodings so renames can't reorder them.
   - Renaming a definition or any local must never change a hash. Two agents that write the same function get the same hash.
2. **Store:** SQLite (`rusqlite` with `bundled`) at `<project>/.ore/store.db`.
   - Tables: `defs` (hash, core bytes, canonical text, type, effects, deps), `names` (name, hash, set_at, active), `tests` (hash, source, deps, last result per dependency hash set).
   - The canonical text comes from L2's printer, and it is what a model gets back from `ore get`.
3. **Commands** (JSON lines):
   - `ore add FILE`: check, then store every definition and test, and bind the names.
   - `ore edit NAME 'one line'`: replace one definition.
     - Parse and check it against the store's current namespace, then store the new hash and rebind the name.
     - Propagate: every dependent is re-hashed (its dependency changed) and re-checked; if it no longer types, the edit is refused with the dependent's diagnostics and nothing is written.
     - Re-run exactly the tests whose dependency set changed.
     - Print `{"k":"edit","name":...,"hash":...,"changed":[...],"tests":{"passed":n,"failed":m},"failing":[...]}`.
   - `ore get NAME...` prints canonical text for models to read.
   - `ore ls` prints names with types.
   - `ore find "Str -> [Str]"`: search by type, unifying against the library and the store, most specific first. Name fragments also work.
   - `ore rm NAME` refuses when something still depends on the name.
4. **Check cache:** types keyed by hash. Re-checking an unchanged file infers nothing (G5's "zero work"). Report how much work a second `ore check` does.

## G2 measurement (stop rule, second check)
Use L1's harness (`bakeoff/`) and add an `edits` mode:
- 30 change requests on finished bake-off programs (15 general, 15 domain). For example: "also return the count", "round to cents", "skip blank lines", "add a 5% markup line", "treat holidays as a parameter". Each has updated tests.
- **Ore side:** the model gets the program's names and types from `ore ls` (plus `ore get` of what it asks for), the request and the card. It answers with only the changed or new definition lines, which go through `ore edit`/`ore add`.
- **Python side:** the model gets the whole Python file and the request. It answers with only the changed or new functions, in full, which replace those functions. This is a generous baseline.
- Sonnet and Codex. Up to 2 fix rounds. Record output tokens, first-try pass and final pass.
- Report G2 as the ratio of Ore to Python output tokens per accepted change. If the ratio is > 0.8, put STOP in the first line of the report.

## Gate (run once, at the end)
- **Rename invariance:** take 50 corpus definitions, rename every name in them, and check the hashes are unchanged.
- **Propagation:** on a 3-level dependency chain, an edit at the bottom re-checks exactly the chain and re-runs exactly its tests.
- `find` returns `lines` and `words` for `Str -> [Str]`.
- G2 as above.
- One `python scripts/cargo.py check --workspace`.
